Features

The Configuration page allows the configuration of the repository provider (BitBucket), its pipelines, Slack, the emailer, etc.

The Repos page shows the list of all repositories Yapily has. You can view the README.md and the bitbucket-pipelines.yml file contents, as well as the details of each repository by clicking on the repository name.

The repository details page can be visited by clicking on a repository's name. Most pages give you this ability.

This page has all the tools, in one place, to trigger pipeline runs in the development and staging environments. You can run any of the pipeline commands defined in the repository's bitbucket-pipelines.yml file. You can run such commands on any branch. The default is "master".

You can also schedule pipeline runs. The scheduler is built-in and it does not use the BitBucket scheduler.

This page allows you to stop running pipeline runs, as well, but only the ones that were triggered using this application.

The table, at the bottom of this page, shows all the pipeline runs triggered using this application along with useful information for each run. When a run is triggered, then the system uses its built-in polling engine to update the run's status.

The Test Run Activity page shows all pipeline runs triggered using this application along with useful information.

The Blame Board page shows all people/committers that caused pipeline runs, triggered using this application, to fail in the last week, along with some statistics.

The Blame Calendar page shows a calendar of pipeline run failures and their fixes.

The Kanban Board page shows a Kanban-like board with 3 columns. The first shows the currently-running pipeline runs triggered using this application along with useful information. The second shows the failed pipeline runs that have not been fixed yet. The third column shows the fixed pipeline runs.

The "Update Fix Timestamps of Failed Test Runs" button on the top-right of the top navigation bar finds all the recorded failed runs that do not have a recorded fix timestamp and checks the next up-to-50 pipeline runs to determine if the failed run on the environment and branch it run against has succeeded. If yes, then it stores the fix timestamp and that timestamp can be seen in various places in the application.

The Repository Group page allows the creation of groups of repositories for the convenience of running e2e-tests with one click.

The Home page shows a dashboard of various analytics.
